# StuEdit 보안 가이드 및 사용자 접근 매뉴얼

## 1. 보안 아키텍처 개요

StuEdit는 **Spring Security 4.x** 기반의 인증/인가 체계를 사용합니다.

```
[사용자 브라우저]
      │
      ▼
[Spring Security Filter Chain]
      │
      ├─ UsernamePasswordAuthenticationFilter  ← 로그인 처리
      ├─ SecurityContextPersistenceFilter       ← 세션 인증 정보 유지
      └─ FilterSecurityInterceptor              ← URL 접근 제어
                  │
                  ▼
      [CustomUserDetailsService]
                  │
              TB_USER (DB 조회)
                  │
              BCryptPasswordEncoder (비밀번호 검증)
```

---

## 2. 인증 (Authentication)

### 2.1 로그인 처리 흐름

1. 사용자가 `/user/login.do` 페이지에서 아이디/비밀번호 입력
2. 폼이 `/user/loginProc.do` 로 POST 전송 (Spring Security 인터셉트)
3. `CustomUserDetailsService.loadUserByUsername()` 호출 → TB_USER 조회
4. BCrypt 알고리즘으로 입력 비밀번호 vs DB 해시값 비교
5. 인증 성공 시 `CustomLoginSuccessHandler` 실행:
   - `last_login_date` DB 업데이트
   - 권한에 따라 대시보드(`/main.do`)로 리다이렉트
6. 인증 실패 시 `/user/login.do?error=true` 로 리다이렉트

### 2.2 비밀번호 보안 정책

| 항목 | 정책 |
|------|------|
| 암호화 방식 | BCryptPasswordEncoder (단방향 해시) |
| 솔트 | BCrypt 자동 생성 (랜덤 솔트 포함) |
| 최소 길이 | 제한 없음 (운영 시 8자 이상 권장) |
| 복호화 | 불가 (단방향) — 분실 시 초기화만 가능 |

### 2.3 세션 관리

| 항목 | 설정 |
|------|------|
| 동시 접속 수 | **1개** (중복 로그인 방지) |
| 세션 만료 시 | `/user/login.do?sessionExpired=true` 리다이렉트 |
| 세션 타임아웃 | Tomcat 기본값 (30분) |

## 3. 인가 (Authorization)

### 3.1 권한 체계

| 권한 | 설명 | 계층 |
|------|------|------|
| ROLE_ADMIN | 시스템 관리자 | 상위 권한 |
| ROLE_STUDENT | 일반 학생 | 하위 권한 |

> `ROLE_ADMIN > ROLE_STUDENT` — 관리자는 학생 권한의 모든 기능 사용 가능

| 기능 | ROLE_ADMIN | ROLE_STUDENT |

| 1:1 문의 작성 | O | O |
| 1:1 문의 답변 | O | X |
| 비밀글 조회 | O (전체) | O (본인만) |

### 3.3 URL 접근 제어 설정

`context-security.xml` 에 정의된 주요 URL 패턴:

```xml

<!-- 로그인한 모든 사용자 -->
/main.do, /chatbot/**, /notice/list.do, /notice/detail.do
/inquiry/insert.do, /survey/participate.do, /schedule/list.do

<!-- 관리자 전용 -->
/student/**, /grade/insert.do, /grade/update.do, /grade/delete.do
/attend/insert.do, /attend/update.do, /attend/delete.do
/notice/insertForm.do, /notice/insert.do, /notice/update.do, /notice/delete.do
/survey/insertForm.do, /survey/insert.do, /survey/delete.do
/survey/result.do, /schedule/insertForm.do, /schedule/insert.do
/schedule/update.do, /schedule/delete.do, /inquiry/answer.do
```

## 4. CSRF 보호

모든 POST 요청에 CSRF 토큰이 필요합니다.

### 4.1 JSP 폼에서 CSRF 토큰 사용

```jsp
<%@ taglib prefix="sec" uri="http://www.springframework.org/security/tags" %>
<form method="post" action="/student/insert.do">
    <sec:csrfInput/>
    <!-- 나머지 폼 필드 -->
</form>
```

### 4.2 Ajax 요청에서 CSRF 토큰 사용

```javascript
var csrfToken = $("meta[name='_csrf']").attr("content");
var csrfHeader = $("meta[name='_csrf_header']").attr("content");

$.ajax({
    url: '/file/upload.do',
    type: 'POST',
    beforeSend: function(xhr) {
        xhr.setRequestHeader(csrfHeader, csrfToken);
    },
    ...
});
```

## 5. 입력값 검증 및 XSS 방지

### 5.1 서버 측 검증

- 모든 입력값은 컨트롤러 또는 서비스 레이어에서 검증
- 필수값 누락, 길이 초과, 형식 오류 시 오류 메시지 반환
- SQL Injection 방지: MyBatis `#{}` 파라미터 바인딩 사용 (`${}` 사용 금지)

### 5.2 XSS 방지

JSP에서 출력 시 JSTL `<c:out>` 또는 EL 함수를 통한 이스케이프 처리:

```jsp
<!-- 안전한 출력 -->
<c:out value="${student.studentName}"/>

<!-- JavaScript 내 출력 시 HTML 이스케이프 함수 사용 -->
function escapeHtml(text) {
    return text.replace(/&/g,'&amp;')
               .replace(/</g,'&lt;')
               .replace(/>/g,'&gt;')
               .replace(/"/g,'&quot;');
}
```

### 5.3 파일 업로드 보안

| 항목 | 설정 |
|------|------|
| 최대 파일 크기 | 10MB (dispatcher-servlet.xml) |
| 저장 파일명 | UUID 자동 생성 (원본 파일명 미사용) |

## 6. 사용자 접근 매뉴얼

### 6.1 관리자 (ROLE_ADMIN) 접근 절차

#### 로그인
1. 브라우저에서 시스템 URL 접속 (`http://[서버주소]/StuEdit`)
2. 아이디: `admin`, 비밀번호: `admin1234` (초기 계정)
3. **운영 환경에서는 반드시 비밀번호 변경 필요**

#### 비밀번호 변경
1. 우측 상단 사용자명 클릭 → 마이페이지
2. 비밀번호 변경 탭 선택
3. 현재 비밀번호 입력 후 새 비밀번호 설정

#### 관리자 계정 추가
> 현재 버전은 DB 직접 INSERT 방식으로 계정 추가
```sql
INSERT INTO TB_USER (login_id, user_pw, user_name, role)
VALUES ('newadmin', '$2a$10$[BCrypt해시값]', '새관리자', 'ROLE_ADMIN');
```

### 6.2 학생 (ROLE_STUDENT) 접근 절차

#### 계정 발급 방법
1. 관리자가 학생 등록 시 계정 자동 생성
2. 초기 비밀번호는 관리자로부터 별도 안내

#### 로그인
1. 시스템 URL 접속
2. 발급받은 학번(아이디)과 비밀번호 입력

#### 접근 가능 메뉴
- 대시보드: 전체 현황 (본인 성적/출결 통계)
- 내 성적: 학기별 성적 조회
- 내 출결: 출결 현황 조회
- 공지사항: 전체 공지 조회
- 1:1 문의: 문의 작성 및 답변 확인
- 설문조사: 진행 중인 설문 참여
- 학사 일정: 학사 캘린더 조회
- AI 챗봇: 학업 관련 AI 상담

### 6.3 세션 만료 및 재로그인

- 30분 이상 미사용 시 자동 로그아웃
- 세션 만료 후 화면 조작 시 로그인 페이지로 자동 이동
- 로그인 페이지 상단에 "세션이 만료되었습니다" 메시지 표시

## 7. 운영 보안 체크리스트

### 7.1 배포 전 필수 조치

- [ ] 기본 관리자 계정(`admin/admin1234`) 비밀번호 변경
- [ ] 기본 학생 계정(`student01/student1234`) 비밀번호 변경 또는 삭제
- [ ] `gemini.properties` API 키 실제 키로 교체 (형상 관리 제외)
- [ ] DB 접속 계정 최소 권한 부여 (SELECT/INSERT/UPDATE/DELETE만)
- [ ] 파일 업로드 디렉토리 쓰기 권한 설정 (Tomcat 실행 계정만)
- [ ] HTTPS 적용 (SSL 인증서 설치 및 Tomcat 설정)
- [ ] `schema.sql`, `dummy-data.sql` 서버에서 제거

### 7.2 정기 운영 보안 점검

| 주기 | 점검 항목 |
|------|----------|
| 주 1회 | 로그인 실패 로그 확인, 비정상 접근 여부 확인 |
| 월 1회 | 미사용 계정 비활성화 (`use_yn='N'`) |
| 분기 1회 | 비밀번호 변경 안내 및 강제 변경 정책 적용 |
